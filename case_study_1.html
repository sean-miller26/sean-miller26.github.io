Establishing the Zooniverse Design System

Role: Product Designer
Scope: Design system, systems thinking
Outcome: Unified design language, reduced design debt

Overview

Zooniverse is the largest platform for people-powered research. Millions of volunteers contribute to real projects in fields like astronomy and ecology.

Over more than a decade, the product grew organically. Different teams built pages and features over time. Most UI decisions happened in code, without a shared design foundation. The result was significant design debt across the platform.

When the engineering team began planning a front-end migration, we treated it as a reset. I used the marketing landing page and the logged-in homepage as starting points for a new UI framework.

This case study covers a multi-year effort to build a scalable design system for the entire product.

The Problem: Design Debt and Legacy Architecture

The UI reflected years of incremental work:

  • Developers built pages independently, often without design input
  • Similar components existed in multiple variations
  • Typography, spacing, and color usage changed from page to page
  • New features required solving the same design problems again

The previous front-end architecture made reuse difficult. Consistency was hard to maintain.

Reframing the Goal

While redesigning the homepages, I stepped back and asked broader questions:

  • What foundational elements are missing?
  • How can one decision scale across dozens of pages?
  • How should design align with the new front-end architecture?
  • How can I design elements with our user base in mind?

Establishing the Foundations

We started with the public landing page.

Visual Language

I audited existing pages to see where patterns aligned and where they broke down. From there, we defined:

  • Buttons and calls to action, which had varied in size, color, and behavior
  • Core layout and spacing rules to create clear hierarchy
  • A more disciplined use of established brand colors

As these components shipped, consistency became built in. It no longer depended on manual effort.

Accessibility as a Baseline

Accessibility issues had accumulated over time. Instead of fixing contrast or focus states case by case, we built accessibility into the system from the start. Every component met these standards by default.

Driving Adoption Through the Logged-In Homepage

The logged-in homepage was the first internal surface to adopt the new system.

Unlike the marketing page, it needed to support frequent use, personalization, and clear paths to contribution. It used a wide range of shared components and set a new baseline for how the product should look and feel.

Documentation evolved alongside it and focused on:

  • Usage guidance based on real production examples
  • Shared patterns built for reuse
  • A common vocabulary between design and engineering

Investing in this page upfront gave us reusable components that made future work faster and simpler.

Scaling Across Project Pages

Project pages are where teams host their research project. Teams upload user-generated content in different formats and levels of quality, so the system had to handle variation across projects without breaking.

Using system components, we focused on:

  • Modern, familiar interaction patterns across projects
  • Clear paths to participation
  • Flexible layouts for user-generated content

Impact

  • Reduced design and technical debt
  • Clear, reusable patterns
  • Faster iteration through Storybook integration
  • Improved accessibility, usability, and SEO
  • A more consistent, modern experience

These three pages became reference implementations. The public landing page clarified the mission for new visitors. The logged-in homepage improved orientation for returning users. The project page showed the system could scale across diverse scientific content.

Reflection

For a long-running platform like Zooniverse, consistency was not about visual polish. It was about making future changes easier.

The new architecture created a chance to address years of accumulated debt. The design system ensured that reset could scale.

This work reinforced that the most durable design decisions happen at the systems level. The right foundations make every future screen easier to build well.

By investing in that foundation, we created infrastructure that will support the platform for years.

Lessons Learned

  • Cross-functional alignment early matters: This project touched infrastructure, content, and marketing. Close collaboration ensured design decisions were technically feasible, on-brand, and rooted in real user needs.
  • Clarity before inspiration: While storytelling motivates, users must first understand what Zooniverse is before they can feel inspired by it.
  • Systems thinking scales better than pixel-pushing: The highest-leverage design work often happens at the component and pattern level, not in individual layouts.
  • Documentation is design work: A system only succeeds when teams understand not just how to use it, but why it exists.

This project reinforced that designing for sustainability means building systems that make the right thing the easy thing.
